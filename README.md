## Project Overview

This repository is the **end-to-end analytical workflow** for an e-commerce company:

1. We **generate** synthetic but realistic datasets (customers, products, orders, line items, returns) that include intentional data quality issues.
2. We **profile and remediate** those issues with documented decisions.
3. We **transform** the cleaned data into a star-schema fact table and derived business tables.
4. We run **exploratory data analysis** (Matplotlib + Seaborn).
5. We surface **business insights and recommendations** in a structured finding / evidence / impact / recommendation format.
6. We ship an **interactive dashboard** (Plotly Dash) for stakeholders.

It is intentionally built to look like the work of a junior analyst - clear, reproducible, business-oriented, and well-documented.

---

## Business Problem

A mid-size e-commerce company needs answers to questions like:

- Are sales growing? Seasonally?
- Which products and categories drive revenue vs profit?
- Who are the most valuable customers?
- Are we leaking margin on high-volume / low-margin SKUs?
- Where should we invest marketing dollars next quarter?

This project answers those questions with data, code, and charts, and closes with a **90-day action plan**.

## Dataset

The data is generated by `scripts/generate_data.py`. Five CSVs are produced:

| File | Rows (~) | Description |
|------|---------:|-------------|
| `customers.csv` | 5,000 | Customer master data |
| `products.csv`  | 300 | Catalog |
| `orders.csv` | 25,000 | Order header |
| `order_items.csv` | 70,000 | Order line items |
| `returns.csv` | 5,600 | Returns |

All datasets include **intentional data quality issues** that must be remediated during the cleaning phase (nulls, duplicates, mixed date formats, inconsistent category labels, negative prices, outliers...). This is part of the analytical work, not a bug.

---

## Data Quality

We use a **PROBLEM - IMPACT - SOLUTION** framework to document every issue we find. The full inventory is in `notebooks/01_data_quality.ipynb`. Highlights:

| Problem | Impact | Solution |
|---------|--------|----------|
| Exact duplicate rows | Inflated counts | Drop duplicates |
| Mixed date formats | Time-series fails | Multi-format parse |
| Inconsistent region / category / status labels | Grouping splits | Map to canonical labels |
| Negative prices / quantities | Wrong revenue | Impute / cap |
| Extreme outliers | Skewed averages | Cap at 99th percentile |
| Null emails / phones / regions | Segmentation gaps | Impute or bucket as 'Unknown' |

## Data Cleaning

Implemented in `src/cleaning.py`. Deterministic, side-effect-free functions:

- `clean_customers(df)`
- `clean_products(df)`
- `clean_orders(df)`
- `clean_order_items(df)`
- `clean_returns(df)`

Each returns a new, cleaned DataFrame. Output is persisted to `data/processed/`.

---

## Data Transformation

Implemented in `src/transformation.py`. Produces:

- `fact_sales` (line-item grain with revenue, cost, profit, profit_margin, returns, dates...)
- Monthly / category / region / channel aggregates
- RFM segments (`Champions`, `Loyal Customers`, `At Risk`, ...)
- Top / slow-moving products

Implemented in `src/metrics.py`:

- `total_revenue`, `total_profit`, `profit_margin`
- `average_order_value`, `return_rate`
- `customer_lifetime_value` (CLV proxy)

## Key Metrics

| Metric | Definition |
|--------|------------|
| **Revenue** | sum of `net_revenue` (line price x quantity, net of discounts) |
| **Profit** | `net_revenue - cost` |
| **Profit Margin** | `profit / revenue` |
| **AOV** | `revenue / number_of_orders` |
| **Return Rate** | items returned / items sold |
| **CLV (proxy)** | `AOV * frequency * 3-yr horizon` |
| **RFM** | Recency / Frequency / Monetary quartile scoring |

## Key Insights

The full list (10 findings) is in `notebooks/05_business_analysis.ipynb` and `reports/business_report.md`. Examples:

- "Category X represents 31% of revenue but only 14% of total profit." -> rebalance merchandising.
- "Top 20% of products drive ~80% of revenue." -> tier inventory policies.
- "Champions + Loyal Customers represent <20% of the base but >50% of revenue." -> loyalty program.
- "Q4 is 25-40% above the monthly average." -> Q4 inventory lock by September.

Each insight follows: **Finding - Evidence - Impact - Recommendation**.

---

## Business Recommendations (summary)

1. **Q4 inventory lock** for the top 20% SKUs by September.
2. **Renegotiate cost** on the top-10 high-volume / low-margin SKUs.
3. **Loyalty MVP** for Champions + Loyal Customers.
4. **Win-back campaign** for the "At Risk" RFM segment.
5. **Localized acquisition test** in the bottom 2 regions.
6. **Clearance** for slow-moving SKUs.
7. **Sizing / fit guides** for the highest-return category.

See `reports/business_report.md` for the full 90-day plan.

## How to Run

```bash
# 1. Clone
git clone <your-repo-url>
cd ecommerce-analytics

# 2. (Optional) create a virtual environment
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Generate the synthetic datasets (optional - already included)
python scripts/generate_data.py

# 5. Run the notebooks in order
jupyter lab
# 01 -> 02 -> 03 -> 04 -> 05

# 6. Launch the dashboard
python dashboard/app.py
# then open http://127.0.0.1:8050
```
